# Web UI 真实浏览器回归报告

> 日期：2026-11-01
> 环境：macOS 15.7.1 arm64；Chrome（Playwright MCP 驱动）；Server `127.0.0.1:18500`
> 被测版本：本轮功能补齐后的 `vmon_server` + `vmon_agent` + 种子数据
> 结论：14 个原始视图完成真实点击回归（新增异常、仪表板视图也已做交互验证）；发现并修复 3 个前端问题；无未捕获 JS 异常。

## 1. 测试方法

1. 启动真实 `vmon_server`（token `ui-token`，工作目录 `/tmp/vmon-ui-test/server`）与
   `vmon_agent`（UDS `/tmp/vmon-ui-test/agent.sock`）；Agent 开启 `--process-metrics`
   以覆盖进程指标。
2. 通过 `curl` 调用真实接口播种数据：3 条 trace（含错误 Span 与跨服务链路）、
   4 条事件、1 条剖析（180 样本折叠栈）、2 个 SLO、1 条指标规则、1 条崩溃。
3. 用 Playwright MCP 打开 `http://127.0.0.1:18500/`，逐视图点击按钮、填写表单、
   提交查询，再用 `browser_evaluate` 读取 DOM 文本/SVG 数量做断言。
4. 同一 URL 的 hash-only 跳转不会重新加载页面，测试统一用 `?v=N#view` 强制真实导航；
   `127.0.0.1` 与 `localhost` 的 localStorage 相互隔离，令牌需在各自 origin 保存。

### 2.1 鉴权与错误提示

| 操作 | 结果 |
|---|---|
| 将 localStorage 令牌改为 `bad-token` 后刷新 | 页面不崩溃，toast 显示「未授权：请提供 X-Vmon-Token 或 Bearer Token」 |
| 在页面输入正确令牌并点击「保存令牌」 | 令牌写入 localStorage，页面重新加载数据，toast「令牌已保存」 |
| 非法 SLO target | 服务端 400，页面显示中文错误信息，控制台仅记录该 400 请求 |

## 3. 发现并修复的问题

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | Trace 瀑布图与树节点出现巨大负数耗时 | 未结束 Span 的 `end_ns=0`、`duration_ns=0`，旧逻辑用「结束时间 - 开始时间」得到负值 | 新增 `spanMs()`：未结束显示「进行中」，已结束正常显示；瀑布图对未结束 Span 回退到当前 trace 末尾并标注「（进行中）」 |
| 2 | 搜索框输入 `ui-parent-1`（request_id）查不到 trace | UI 只把 `req-`/`REQ` 前缀当 request_id，其余当作服务名 | 服务端新增统一 `q` 子串搜索（trace_id/request_id/task_id/root 服务/root 名称/任意 Span 服务名与名称，忽略大小写）；UI 搜索一律传 `q`；补 Server 单测与 E2E |
| 3 | 服务视图出现 `/bin/zsh`、`./build/vmon_age` 等进程名 | Agent 把进程名写入指标事件的 `service` 字段，Store 将其当作服务观察 | 进程指标不再设置 `service`，只保留 `process`/`pid`/`threads` 标签与 `pid` 字段；E2E 增加「进程指标不得携带 service 标签」回归断言 |

> 说明：崩溃页使用 `div` 列表而非 `table`，早期自动化选择器 `tbody tr` 取不到行，
> 属于测试脚本问题，不是产品缺陷；已改为按 `data-crash` 定位并验证。

## 4. 未覆盖与后续

- 拓扑 SVG 在大量服务/环路下的布局只做了数据量较小的验证，规模压力测试待补；
- 自动刷新依赖定时器，本次验证了开关与数据更新，未做长时间挂机；
- 移动端/小屏布局不在目标范围；
- 浏览器缓存与 hash 路由的差异属于测试环境行为，已在方法中说明。
