# 生产环境零影响设计约束（硬性）

> 版本：v0.1（2026-11-01）
> 适用：CplusTrace / vmon 维测服务
> 结论：**维测是旁路系统。任何维测组件故障、过载、配置错误，都不得改变业务功能、返回结果和可用性。**

## 0. “不影响”的验收定义

| 维度 | 要求 |
|---|---|
| 功能语义 | 业务输入/输出、状态机、错误码、重试语义与接入前完全一致 |
| 可用性 | 维测组件宕机、磁盘满、网络断、队列满，业务仍正常运行 |
| 延迟 | 接入 SDK 后业务 p99 延迟影响 < 1%；gRPC 拦截器单次开销 < 100 µs |
| CPU | SDK 常驻 CPU < 1%；Agent < 1 核；重采集默认关闭 |
| 内存 | SDK 常驻 RSS < 15 MB；Agent < 512 MB（可配） |
| 磁盘 | Agent 本地 WAL 有硬上限；磁盘水位触发丢弃，绝不占满业务盘 |
| 网络 | Agent 上报限速；断网只缓存，不重试风暴 |
| 可回滚 | 禁用开关/卸载后，业务行为与接入前一致，无需数据迁移 |
| 依赖 | 不引入与目标系统冲突的 gRPC/protobuf/abseil/OpenSSL 版本 |

## 1. 接入形态与影响面

| 级别 | 业务进程改动 | 影响面 | 默认策略 |
|---|---|---|---|
| L0 零改造 | 无 | 极低：Agent 只读 `/proc`、日志文件、core | **默认**，覆盖全部进程 |
| L1 轻改造 | 链接 libvmon、注册 interceptor、日志兼容层、心跳 | 可控：热路径有少量原子操作与环形队列写入 | 仅核心 10–20 个进程，灰度开启 |
| L2 标准改造 | 关键函数 `VMON_SPAN`、线程池/队列/回调包装 | 中等：需白名单、采样、深度上限 | 仅重点模块 |
| L3 深度改造 | 全量插桩、分配器 hook | 较高：必须限时、限进程、可回滚 | 仅 1–2 个疑难进程，按需 |

**硬性规则**：

- 默认先上 L0；L1 必须经过生产灰度；没有 L0 兜底的进程不允许直接上 L2/L3。
- L2/L3 只能在指定实例开启，必须带 TTL 自动关闭。
- 任何级别都必须支持“运行中一键降级到 L0”。

## 2. 进程与资源隔离

### 2.1 独立进程

- `vmon-agent`、`vmon-server` 与业务进程**不同进程、不同 cgroup**。
- Agent 不注入业务进程，不共享内存，不持有业务锁。
- 业务进程只通过 UDS 与控制通道交互；UDS 不可用时自动降级。

### 2.2 systemd 资源限额示例

```ini
[Service]
Type=simple
ExecStart=/opt/vmon/bin/vmon-agent --config /etc/vmon/agent.toml
Restart=always
RestartSec=2s

# 资源上限：Agent 永远不能挤占业务
CPUQuota=100%
MemoryHigh=384M
MemoryMax=512M
IOWeight=50
Nice=10
OOMScoreAdjust=500
TasksMax=256
LimitNOFILE=65535
```

- `OOMScoreAdjust=500`：内存紧张时优先杀 Agent，不杀业务。
- `MemoryMax`：硬上限，触发 OOM 而不是拖垮节点。
- `IOWeight=50`：磁盘竞争时让业务优先。
- `Nice=10`：CPU 竞争时让业务优先。

### 2.3 磁盘与网络

- WAL 目录独立挂载或独立配额，默认上限 2 GB，可配。
- 磁盘水位 > 80%：停止低价值日志采集；> 90%：只保留错误与崩溃；> 95%：停止写入并告警。
- 上报带宽默认限制为 10 Mbps/节点，可配；断网时指数退避，不做重试风暴。
- 日志采集只读，不轮转、不删除、不加文件锁。

## 3. SDK fail-open 契约

所有 SDK 公共 API 必须满足：**不抛异常、不阻塞、不改变业务控制流**。

| 故障场景 | SDK 行为 | 业务影响 |
|---|---|---|
| 初始化失败（配置错、权限不足、依赖缺失） | 标记 disabled，所有 API 变为空操作 | 无；业务继续 |
| 环形队列满 | 丢弃当前事件，`drop_count++` | 无；不等待、不反压业务 |
| Agent 不可达 | 丢弃或写本地有界缓冲；缓冲满继续丢 | 无 |
| 日志写入失败 | 回退到原有日志路径；原路径也失败则丢弃并计数 | 无 |
| gRPC header 注入失败 | 不注入，RPC 继续 | 无；该跳无 trace |
| 上下文提取失败 | 新建独立 trace，不拒绝请求 | 无 |
| 崩溃处理器失败 | 恢复默认处置并重新抛出信号 | 保持原有 core dump 行为 |
| fork/exec | `pthread_atfork` 重置 ring、锁、pid；exec 通过环境变量传递上下文 | 无 |
| shutdown | 限时 flush（默认 200 ms），超时直接丢弃 | 无；不阻塞退出 |
| SDK 内部异常 | 边界处 catch-all，绝不跨 API 传播 | 无 |
| 配置热加载失败 | 保留上一份有效配置 | 无 |

**禁止事项**：

- 禁止在 SDK 内调用 `abort()`、`exit()`、`std::terminate()`。
- 禁止在信号处理器里 malloc、加锁、格式化、写文件、抓栈、符号化。
- 禁止把 SDK 自身错误写回同一条日志管道造成递归。
- 禁止在业务线程做网络、磁盘、压缩、序列化、DNS。

## 4. 热路径规则

| 规则 | 说明 |
|---|---|
| 零动态分配 | 热路径不 `new`/`malloc`/`std::string`；用固定缓冲区与字符串 intern |
| 零锁 | 每线程 SPSC 环形队列；跨线程只传递 `causality.id` |
| 零系统调用 | 时间用 `clock_gettime`（vDSO）；pid/start_time 启动时缓存 |
| 零 IO | 不写文件、不发网络、不读配置 |
| 零压缩/序列化 | 原始事件入队，后台线程批量处理 |
| 零异常/RTTI | 不使用异常传播；关闭 RTTI 不影响业务 |
| 有界内存 | 每线程 ring 固定大小；全局队列固定大小；溢出即丢 |
| 可观测丢弃 | `drop_count`、`queue_depth`、`flush_latency` 作为自监控指标 |
| 目标开销 | span 创建 < 100 ns；Counter p99 < 1 µs；SDK CPU < 1%；RSS < 15 MB |

## 5. gRPC 拦截器安全规则

- **只追加，不修改**：只向 metadata 追加 `traceparent`、`tracestate`、`x-request-id`、`x-task-id`。
- **不改变调用语义**：不改 deadline、不改重试、不改压缩、不改负载均衡、不改凭证。
- **失败即放行**：任何观测逻辑失败都不得让 RPC 失败。
- **流式 RPC**：每条流一个 span；不在每条消息上做阻塞操作。
- **异步 RPC**：上下文通过 wrapper 捕获，不用全局锁；回调线程恢复上下文失败时新建 trace。
- **版本不匹配**：编译期检测 gRPC 版本；不匹配时关闭 adapter，退回 L0，不硬链接。
- **不重复链接**：不把第二份 gRPC/protobuf/abseil 静态链接进业务进程。

### 5.1 老版本 gRPC / protobuf 3.0 的降级路径

目标系统 protobuf 为 3.0，gRPC 可能同年代，不一定有 C++ interceptor。按以下顺序降级，保证业务不受影响：

1. **公共 gRPC 封装层手工注入**：只改一处公共封装，不逐个改调用点；注入失败不影响 RPC。
2. **节点级 sidecar**：零代码，但多一跳；只对无法重编译的进程使用。
3. **L0 兜底**：只做日志序列还原与 eBPF 弱边推断，不承诺精确 trace。

无论哪条路径，都不得改变 RPC 的 deadline、重试、压缩、凭证和错误码。

### 5.2 POCO 线程池适配

- 只做**上下文传递**：在任务提交时捕获 `trace_id`/`span_id`/`causality.id`，工作线程恢复；不改变线程池的线程数、队列策略、调度顺序。
- 提供 drop-in wrapper，保持原有 POCO 接口；业务代码不需要改调用方式。
- wrapper 内部失败（上下文捕获/恢复失败）时，任务照常执行，只是该任务没有因果链。
- 不替换 POCO 的 `ThreadPool`、`NotificationQueue` 实现，不修改其源码。
- 编译时确认 POCO 版本与 `_GLIBCXX_USE_CXX11_ABI` 与目标一致，避免 ABI 冲突。

## 6. 日志兼容层安全规则

- 保留原有宏名、函数名、格式串；业务调用点不改。
- `VMON_DISABLE=1` 或配置 `enabled=false` 时，**完全走原有日志实现**，行为与接入前一致。
- 启用时：
  - ERROR/FATAL 100% 保留，不受采样/限流影响；
  - INFO/DEBUG 可采样、可限流；
  - 每条日志自动带 `trace_id`/`request_id`/`task_id`/`thread.id`；
  - 日志写入失败回退原路径，不阻塞业务。
- 不改变日志级别语义；动态级别只影响 vmon 管理的日志，带 TTL 自动恢复。
- 不把监控/心跳日志继续写进日志文件；转成指标，减少日志量。

## 7. 诊断操作安全规则

| 操作 | 默认 | 约束 |
|---|---|---|
| 读 `/proc`、日志、core | 允许 | 只读；超时；输出截断 |
| 采集线程栈（信号） | 允许 | 低频；只抓地址；离线符号化 |
| `SIGPROF` CPU 采样 | **关闭** | 开启后 99 Hz；限时；恢复原 handler |
| `perf record` | **关闭** | 需审批；限时；限输出；可能受 `perf_event_paranoid` 限制 |
| eBPF uprobe/kprobe | **关闭** | 需审批；CO-RE；无内核模块；资源限额 |
| `gdb`/`ptrace` attach | **禁止** | 会暂停进程；仅故障实例 + 审批 + 限时 |
| 修改日志级别 | 允许但需审计 | TTL 自动恢复；只影响 vmon 日志 |
| 触发 core dump | 需审批 | 限制 core 大小；独立目录；不覆盖业务文件 |
| 执行 shell 命令 | **禁止** | 白名单命令 + 固定参数模板，禁止字符串拼接 |

- 所有诊断命令必须有超时（默认 10 s）、输出上限（默认 1 MB）、`nice`/`ionice` 降权。
- 诊断结果写入独立目录，带审计日志（谁、何时、对哪个进程、执行了什么）。
- 生产环境默认只读；写操作必须二次确认。

## 8. 崩溃与信号安全

- 首选 `core_pattern=|/path/crash-helper`，由内核在进程外触发，不在业务进程内做重活。
- 进程内信号处理器仅做：
  1. 向**预打开**的 fd/memfd `write()` 原始上下文；
  2. 恢复默认 handler；
  3. `_exit()` 或重新抛出信号。
- 信号处理器内禁止：malloc、printf、std::string、加锁、读取 `/proc`、符号化、网络。
- 崩溃产物大小有上限；写满即停，不影响业务磁盘。
- 如果 crash-helper 失败，回退系统默认 core dump；不能吞掉崩溃。
- 崩溃解析、符号化、指纹计算全部在 Agent/Server 离线完成。

## 9. 数据采集安全

- 日志采集：只读 tail，按 inode 跟踪轮转；不加锁、不改权限、不删除。
- `/proc` 采集：只读；限制读取频率；避免读取超大 `smaps` 造成 IO 峰值。
- 环境变量、命令行、配置：默认脱敏；不采集密钥、token、密码。
- 高基数数据（`request_id`、`task_id`、用户 ID）禁止作为指标标签；只作为日志/trace 字段。
- 采集器支持按进程、按服务、按指标白名单启停。
- 任何采集器异常只影响自身，不影响其他采集器与业务。

## 10. 灰度、熔断与回滚

### 10.1 开关

- 全局：环境变量 `VMON_DISABLE=1`、配置 `enabled=false`、CLI `vmonctl disable`。
- 进程级：`VMON_DISABLE=1` 只关闭当前进程。
- 能力级：日志、指标、trace、profiling、eBPF 分别开关。
- 动态级别：按服务/实例/请求开启 DEBUG，带 TTL。

### 10.2 灰度顺序

1. 单节点、单实例、非核心服务；
2. 单服务全部实例；
3. 核心链路 1 个实例；
4. 核心链路全部实例；
5. 全量 L0，按价值逐步 L1。

每一步观察至少 24 小时，对比错误率、p99、CPU、RSS、日志量。

### 10.3 自动熔断

满足任一条件自动降级到 L0 并告警：

- SDK CPU > 2%（持续 5 分钟）；
- SDK RSS > 30 MB；
- 队列丢弃率 > 5%；
- Agent CPU > 1 核或 RSS > 512 MB；
- Agent 写入磁盘 > 配额 90%；
- 业务 p99 较基线上升 > 3%；
- 维测自身错误率 > 1%。

### 10.4 回滚

- 关闭开关 → 业务立即回到原日志/原行为。
- 卸载 Agent → 业务无感知。
- 移除 SDK 链接 → 重新编译即可，无数据迁移。
- 回滚演练每季度一次。

## 11. 验证与验收

| 验证项 | 方法 | 通过标准 |
|---|---|---|
| 功能回归 | 业务全量测试用例 | 100% 通过，返回结果与基线一致 |
| 延迟开销 | A/B 压测，对比 p50/p99 | p99 影响 < 1% |
| 资源开销 | 接入前后 CPU/RSS/IO | SDK CPU < 1%，RSS < 15 MB |
| Agent 宕机 | `kill -9 vmon-agent` | 业务无错误、无延迟抖动 |
| 磁盘写满 | 填满 WAL 分区 | 业务正常；Agent 丢弃低价值数据并告警 |
| 网络中断 | 断开 Agent→Server | 业务正常；恢复后续传 |
| 队列风暴 | 注入高流量日志 | 业务不阻塞；drop_count 可见 |
| 配置损坏 | 写入非法配置 | SDK 降级 disabled；业务继续 |
| 信号风暴 | 高频 SIGSEGV/SIGABRT | crash-helper 限流；业务 core 行为保留 |
| fork/exec | 多进程/exec 场景 | ring/pid 正确重置；无死锁 |
| 长时间稳定 | 72 小时连续运行 | 无内存增长、无 fd 泄漏、无丢关键数据 |
| 生产灰度 | 1–2 周真实流量 | 无业务故障；开销在预算内 |
| 回滚演练 | 关闭/卸载 | 业务行为与接入前一致 |

## 12. 反模式清单（禁止）

- 在业务线程同步写日志文件/发网络。
- 用无界队列缓存事件。
- 在信号处理器里 malloc、格式化、抓栈、符号化。
- 把 `request_id` 作为指标标签。
- 在业务进程内做压缩、序列化、DNS、重试。
- 用 `LD_PRELOAD` 默认注入生产进程。
- 默认 `gdb`/`ptrace` attach 生产进程。
- 默认开启 eBPF/perf 高频采集。
- 让 Agent 与业务共享 cgroup 或磁盘配额。
- 观测失败导致 RPC 失败、请求被拒、日志丢失。
- 未经灰度直接全量开启 L2/L3。
- 把 GPL/AGPL 代码复制进产品源码树。
